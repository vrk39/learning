Object-Oriented Programming: Architect & Tech-Lead Interview Prep

Section 1: Basic & Intermediate Q&A​

Question:

How do the rules of preconditions, postconditions, and invariants govern Liskov Substitution Principle (LSP) compliance?

Question:

What is the History Constraint (Constraint on State Changes) in LSP, and how do mutable subclasses violate it?

Question:

Why is exposing raw mutable collection references via getters considered an architectural anti-pattern that shatters encapsulation invariants?

Question:

Why are explicit type-code checks (`instanceof` or `switch` cascades on class tags) considered architectural code smells when implementing the Open/Closed Principle?

Question:

Contrast Role Interfaces with Header Interfaces in the context of Interface Segregation, and explain why Header Interfaces cause high enterprise coupling.

Question:

Why do strict OOP languages enforce invariant or contravariant parameter types during method overriding, and what architectural failure occurs if covariant parameters are permitted?

Question:

How do multi-field state invariants complicate encapsulation, and how does a Rich Domain Model solve them compared to an Anemic Domain Model?

Question:

How do Service Provider Interfaces (SPI) achieve runtime Open/Closed compliance without recompiling core application modules?

Question:

How does the Adapter Design Pattern resolve interface pollution when integrating legacy third-party SDKs that violate ISP?

Question:

What are the compile-time exception rules enforced during method overriding, and how do they preserve LSP substitutability?

Question:

What architectural risks does Self-Encapsulation (calling internal getters/setters instead of raw fields) introduce in deep object inheritance hierarchies?

Question:

How does the Template Method Pattern balance the Open/Closed Principle through controlled inversion of control?

Question:

Why does overriding `equals()` in a subclass while adding new equality fields often break LSP equivalence contracts (Symmetry and Transitivity)?

Question:

How do Value Objects enforce structural encapsulation and eliminate side-effect bugs in distributed domain architectures?

Question:

Why is throwing `UnsupportedOperationException` in interface implementation methods a definitive indicator of an Interface Segregation Principle violation?

Question:

What is the critical structural distinction between Subtyping (interface inheritance) and Subclassing (implementation inheritance)?

Question:

Why are covariant return types safe under LSP, whereas covariant parameter types are fundamentally unsafe?

Question:

How do strict nullability contracts (e.g., `@NonNull` and `@Nullable` annotations) impact LSP compliance during method overriding?

Question:

Explain why strengthening preconditions in a subclass method violates LSP from a client-caller perspective.

Question:

Explain why weakening postconditions in a subclass method violates LSP from a client-caller perspective.

Question:

How do copy constructors and deep cloning routines protect encapsulation invariants against external manipulation?

Question:

Why does returning a direct reference to a mutable internal collection from a getter violate encapsulation, and what is the robust architectural remedy?

Question:

How does the Fragile Base Class Problem undermine OCP, and why does making classes or methods `final` mitigate it?

Question:

How does ISP apply to API gateway contracts and microservice client SDKs to prevent bloated payload dependencies?

Question:

How does switching from direct method calls to an event-driven pub-sub mechanism enhance OCP compliance in enterprise workflows?

Question:

What happens to LSP if a subclass overrides a method to throw a broader or novel checked exception type?

Question:

What is behavioral encapsulation, and why does an anemic domain model destroy object-oriented encapsulation principles?

Question:

How do abstract classes enforce partial structural invariants while interfaces enforce pure behavioral contracts?

Question:

Why is overriding a parent method with a blank or 'no-op' implementation a classic sign of an LSP violation?

Question:

How can interface default methods introduce hidden state coupling and violate clean interface segregation?

Question:

What is the difference between nominal subtyping (compiler-enforced type checks) and behavioral subtyping (runtime semantic guarantees)?

Question:

How does the 'Fat Client' antipattern manifest when consumer modules depend on large, unsegmented interfaces?

Question:

How does replacing rigid conditional logic with a dynamically loaded strategy registry achieve complete OCP compliance?

Question:

What are the risks of exposing internal state mutators inside a fluent builder interface before the final object is built?

Question:

Why does a subclass implementation that shifts a synchronous blocking call to an asynchronous non-blocking future break LSP if client code expects immediate results?

Question:

How do rich domain models protect state invariants during bulk batch updates or database rehydration?

Question:

Why does extending concrete, non-abstract classes for code reuse violate OCP and introduce tight coupling?

Question:

How does role-based interface segregation decouple security permission checks from core domain business logic?

Question:

What is the architectural danger of forcing client code to manage locks externally versus encapsulating thread-safety invariants inside the object?

Question:

How does the classic Circle-Ellipse problem illustrate the failure of modeling behavioral hierarchy through geometric subclassing under LSP?

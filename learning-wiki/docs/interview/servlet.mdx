<Flashcard
  question="What are the main differences between GenericServlet and HttpServlet?"
  answer="* GenericServlet: A protocol-independent abstract class that implements the Servlet interface, allowing servlets to handle any kind of communication protocol (not limited to HTTP).
* HttpServlet: An abstract subclass extending GenericServlet specifically designed to handle HTTP protocol requests by providing specialized methods like doGet(), doPost(), etc."
/>

<Flashcard
  question="What are the common HTTP methods supported in Java Servlets?"
  answer="* GET: Retrieves data from the server (idempotent and safe).
* POST: Submits data to be processed to a specified resource (non-idempotent).
* PUT: Uploads a representation of the specified URI.
* DELETE: Deletes the specified resource.
* HEAD, OPTIONS, and TRACE: Used for metadata retrieval, server capability checks, and diagnostics."
/>

<Flashcard
  question="What is the difference between idempotent and non-idempotent HTTP methods?"
  answer="* Idempotent Methods: Methods (like GET, PUT, DELETE, OPTIONS) that can be called multiple times without changing the initial result beyond the first application.
* Non-Idempotent Methods: Methods (like POST) where making multiple identical requests can produce different results or side effects (e.g., creating multiple duplicate database records)."
/>

<Flashcard
  question="How can you secure a Java servlet against unauthorized access?"
  answer="* Declarative Security: Configure security constraints, authentication types (BASIC, DIGEST, FORM, CLIENT-CERT), and role-based authorization mappings inside the deployment descriptor (web.xml).
* Programmatic Security: Use HttpServletRequest methods like isUserInRole(), getUserPrincipal(), and authenticate() inside the servlet code.
* Transport Security: Ensure HTTPS/SSL is enforced for secure data transmission."
/>

<Flashcard
  question="What is a Servlet Filter and what is its primary purpose?"
  answer="* Definition: A reusable object executed prior to or after a servlet request/response cycle to intercept and process incoming requests or outgoing responses.
* Primary Purpose: Used for cross-cutting concerns such as logging, authentication checking, data compression, encryption, input validation, and character encoding adjustments."
/>

<Flashcard
  question="What are the main differences between FTP and SFTP?"
  answer="* FTP (File Transfer Protocol): A standard network protocol used for transferring files over a network, operating unencrypted by default.
* SFTP (SSH File Transfer Protocol): A secure version of FTP that runs over the Secure Shell (SSH) protocol, encrypting both authentication credentials and data files during transfer."
/>

<Flashcard
  question="How do you handle invalid or expired sessions in Java Servlets?"
  answer="* Session Check: Use `request.getSession(false)` which returns `null` if no active session exists, avoiding automatic creation of a new session.
* Invalidation: Explicitly call `session.invalidate()` during user logout to clear stored attributes and destroy the session.
* Redirection: Use servlet filters or security checks to redirect users with expired sessions back to the login page."
/>

<Flashcard
  question="What are the mechanisms available in Java Servlets to maintain user state across HTTP requests?"
  answer="* HTTP Sessions: Server-side state tracking using `HttpSession` linked via session cookies (e.g., JSESSIONID).
* Cookies: Small text files stored on the client browser and sent automatically with subsequent server requests.
* Hidden Form Fields: Embedding state data directly inside HTML form fields.
* URL Rewriting: Appending the session ID directly to the query string (e.g., `;jsessionid=...`) as a fallback when cookies are disabled."
/>

<Flashcard
  question="How do you create and manage HTTP sessions and cookies in Java Servlets?"
  answer="* Creating Sessions: Use `HttpSession session = request.getSession();` to create a new session or retrieve an existing one.
* Session Attributes: Store and retrieve data using `session.setAttribute(key, value)` and `session.getAttribute(key)`.
* Managing Cookies: Create a cookie via `Cookie cookie = new Cookie('name', 'value');` and attach it to the outgoing response using `response.addCookie(cookie);`."
/>

<Flashcard
  question="What are the main differences between sendRedirect and RequestDispatcher (forward) in Servlets?"
  answer="* sendRedirect(): A client-side redirect that sends a 302 status code, forces a brand new browser request, changes the URL in the address bar, and loses original request attributes.
* RequestDispatcher.forward(): A server-side redirection where control is transferred internally within a single client request, keeping the original URL in the browser and preserving request scope attributes."
/>

<Flashcard
  question="Why must wait(), notify(), and notifyAll() methods be called from within a synchronized block?"
  answer="* Monitor Ownership: These methods operate on the object's monitor lock and require the current thread to own the monitor lock of the object before calling them.
* IllegalMonitorStateException: If invoked outside a synchronized context, the JVM throws an IllegalMonitorStateException at runtime.
* Race Condition Prevention: Ensures thread coordination happens safely without race conditions during state checks and updates."

<Flashcard
  question="What are the main differences between the volatile keyword and synchronized blocks?"
  answer="* Volatile: Ensures visibility of changes to variables across threads by reading/writing directly to main memory, but does not provide atomicity or locking.
* Synchronized: Provides both mutual exclusion (atomicity) and memory visibility by locking access to a critical section or object monitor.
* Use Case: Use volatile for simple flag variables where only visibility matters, and synchronized for compound operations requiring atomic updates."
/>

<Flashcard
  question="What is the life cycle of a thread in Java?"
  answer="* New: The thread has been created using the Thread class but execution has not yet started (start() has not been called).
* Runnable: The thread is ready to run and waiting for CPU allocation from the thread scheduler.
* Blocked / Waiting / Timed Waiting: The thread is inactive, waiting for a monitor lock or waiting for another thread to signal/time out.
* Terminated (Dead): The thread has finished execution or exited abnormally."
/>

<Flashcard
  question="What is an ExecutorService and what are the common types of thread pools?"
  answer="* Definition: An ExecutorService provides a managed thread pool framework to execute asynchronous tasks without manually managing thread lifecycles[cite: 1].
* Fixed Thread Pool: Reuses a fixed number of threads operating off a shared unbounded queue.
* Cached Thread Pool: Creates new threads as needed but reuses previously constructed threads when available.
* Single-Thread Executor: Executes tasks sequentially using a single worker thread.
* Scheduled Thread Pool: Supports periodic or delayed task execution."

<Flashcard
  question="What is a CountDownLatch and how does it function in Java concurrency?"
  answer="* Definition: A synchronization aid that allows one or more threads to wait until a set of operations being performed in other threads completes[cite: 1].
* Mechanism: Initialized with a given count, decremented via countDown(), while waiting threads block at await() until the count reaches zero."
/>

<Flashcard
  question="What are the differences between static variables and volatile variables in multithreading?"
  answer="* Static Variables: Shared across all instances of a class in class-area memory, but do not inherently guarantee thread visibility or atomic updates without synchronization.
* Volatile Variables: Guaranteed to be visible across threads by reading and writing directly to main memory, preventing thread caching optimizations, but still lacking atomicity for compound actions."
/>

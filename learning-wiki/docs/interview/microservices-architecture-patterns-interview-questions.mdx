<Flashcard
  question="What are the SOLID principles in Object-Oriented Design?"
  answer="* Single Responsibility Principle (SRP): A class should have only one reason to change.
* Open/Closed Principle (OCP): Software entities should be open for extension, but closed for modification.
* Liskov Substitution Principle (LSP): Objects of a superclass should be replaceable with objects of its subclasses without breaking application correctness.
* Interface Segregation Principle (ISP): Clients should not be forced to depend on interfaces they do not use.
* Dependency Inversion Principle (DIP): Depend upon abstractions, not on concretions."
/>

<Flashcard
  question="What is the Saga design pattern in microservices and what are its two main types?"
  answer="* Definition: A pattern to manage data consistency across microservices in a distributed transaction without traditional ACID transactions.
* Orchestration Saga: A central orchestrator service coordinates transaction steps and manages compensating actions on failure.
* Choreography Saga: Services listen to events and execute local transactions independently without a central coordinator."
/>

<Flashcard
  question="What is the Event-Driven architecture pattern and what are its key components?"
  answer="* Definition: A software architecture paradigm where decoupled services communicate asynchronously by producing and consuming events.
* Key Components: Event Producers (generate events), Event Channels / Brokers (transit events, like Kafka or RabbitMQ), and Event Consumers (process events reactively)."
/>

<Flashcard
  question="What is the CQRS (Command Query Responsibility Segregation) design pattern?"
  answer="* Definition: A pattern that separates read operations (Queries) from write operations (Commands) into distinct models or database stores.
* Purpose: Allows independent scaling, optimization, and tuning of read-heavy and write-heavy workloads separately."
/>

<Flashcard
  question="What is the Two-Phase Commit (2PC) protocol and why is it often avoided in modern microservices?"
  answer="* Definition: An atomic commitment protocol ensuring all nodes in a distributed transaction either commit or abort.
* Limitations: It is a blocking protocol; if the coordinator fails or a network partition occurs, participant nodes can remain locked indefinitely, severely hurting availability and throughput."
/>

<Flashcard
  question="What is Event Sourcing and how does it differ from traditional state-based persistence?"
  answer="* Traditional Persistence: Stores only the current state of an entity in database rows, overwriting values on updates.
* Event Sourcing: Stores every change to the application state as a sequence of immutable, append-only events; current state is derived by replaying the event log, providing a complete audit trail and time-travel querying capabilities."
/>

<Flashcard
  question="What are the differences between Blue-Green Deployment and Canary Deployment strategies?"
  answer="* Blue-Green Deployment: Maintains two identical production environments (Blue and Green); one is live while the other is updated, allowing instant, zero-downtime traffic switching via load balancers.
* Canary Deployment: Gradually rolls out a new version of an application to a small subset of users (canary group) while monitoring performance and errors before rolling it out to the entire user base."
/>

<Flashcard
  question="What is a Service Mesh and what problems does it solve in microservices?"
  answer="* Definition: A dedicated infrastructure layer (e.g., Istio, Linkerd) built directly into a microservices architecture to manage service-to-service communication transparently via sidecar proxies.
* Problems Solved: Handles traffic management, service discovery, load balancing, mutual TLS (mTLS) security, resilience (retries/circuit breaking), and telemetry without altering application source code."
/>

<Flashcard
  question="What is the principle of 'Composition over Inheritance' in Object-Oriented Design?"
  answer="* Definition: A design principle suggesting that classes should achieve code reuse and polymorphic behavior through containment (composition) rather than class inheritance.
* Purpose: Avoids rigid, deeply coupled class hierarchies, reduces side effects from parent class modifications, and prevents the fragile base class problem."
/>

<Flashcard
  question="What is the difference between CountDownLatch and CyclicBarrier in Java concurrency?"
  answer="* CountDownLatch: A one-shot synchronization aid that allows one or more threads to wait until a set of operations performed in other threads completes (the count cannot be reset).
* CyclicBarrier: Allows a fixed number of threads to wait for each other at a common barrier point, and it can be automatically reset and reused for subsequent coordination cycles."
/>

<Flashcard
  question="What is the difference between Deadlock and Livelock in concurrent systems?"
  answer="* Deadlock: Threads are permanently blocked in a waiting state, consuming zero CPU cycles while waiting for resources held by each other.
* Livelock: Threads are actively changing their states and responding to each other in a continuous loop without making any actual forward progress, consuming high CPU utilization."
/>

<Flashcard
  question="What is the Transactional Outbox Pattern in microservices and why is it used?"
  answer="* Definition: A design pattern used to reliably publish domain events to a message broker alongside database updates within a single local transaction.
* Mechanism: Instead of publishing directly, events are saved to an 'outbox' table in the same database transaction; a separate background worker or CDC (Change Data Capture) tool reads the outbox table and publishes the messages to the broker, ensuring dual-write consistency."
/>

<Flashcard
  question="What is a JVM Safepoint and why is it important for Garbage Collection?"
  answer="* Definition: A specific point during program execution where the state of all threads is known to be consistent and safely inspected by the JVM runtime.
* Importance: Required for Stop-The-World (STW) operations like Garbage Collection, thread dumps, and biased locking revocation, because threads cannot be safely modified while actively executing bytecode."
/>

<Flashcard
  question="What is the Actor Model in concurrent programming and how does it work?"
  answer="* Definition: A conceptual model of concurrent computation where primitive units called 'Actors' encapsulate state, behavior, and a mailbox.
* Mechanism: Actors do not share memory; instead, they communicate exclusively by passing immutable messages asynchronously to each other's mailboxes, eliminating explicit thread locking and race conditions."
/>

<Flashcard
  question="What is the difference between Load Testing, Stress Testing, and Spike Testing?"
  answer="* Load Testing: Evaluates system behavior under expected normal and peak user traffic volumes to verify performance metrics.
* Stress Testing: Pushes the system beyond normal operational capacity (often until breaking point) to identify failure modes, bottlenecks, and recovery behavior.
* Spike Testing: Tests system resilience against sudden, extreme surges in traffic volume for short durations."
/>

<Flashcard
  question="What is a Tail-Recursive function and why is tail-call optimization important?"
  answer="* Tail-Recursion: A recursive function where the recursive call is the absolute final operation performed by the function, leaving no pending operations to execute after the recursive step returns.
* Tail-Call Optimization (TCO): A compiler optimization where stack frames for tail-recursive calls are reused instead of allocating new stack space, preventing stack overflow errors."
/>

<Flashcard
  question="What is an Immutable Object and what are its benefits in concurrent programming?"
  answer="* Definition: An object whose internal state cannot be modified whatsoever after it is constructed.
* Benefits: Naturally thread-safe, requires no synchronization locks, immune to race conditions, can be safely shared across multiple threads, and simplifies caching logic."
/>

<Flashcard
  question="What is the difference between a Blue-Green deployment and a Rolling deployment?"
  answer="* Blue-Green Deployment: Maintains two identical production environments (Active/Inactive), switching router traffic instantaneously to the new version for zero-downtime cutovers.
* Rolling Deployment: Gradually replaces instances of the old version with the new version incrementally across server nodes, reducing resource requirements during deployment."
/>

<Flashcard
  question="What is the difference between a Functional Programming paradigm and Object-Oriented Programming?"
  answer="* Functional Programming: Focuses on pure functions, immutable data structures, and the evaluation of mathematical expressions, avoiding shared mutable state and side effects.
* Object-Oriented Programming: Focuses on encapsulating state and behavior together into mutable objects that interact through method calls and inheritance hierarchies."
/>

<Flashcard
  question="What is Hexagonal Architecture (Ports and Adapters) in software design?"
  answer="* Definition: An architectural pattern that isolates the core domain business logic from external concerns (databases, UI, APIs, third-party services).
* Mechanism: Business logic interacts with the outside world exclusively through 'Ports' (interfaces) and 'Adapters' (implementations), making the core system highly testable and decoupled."
/>

<Flashcard
  question="What is ThreadLocal storage in Java and what are its potential memory leaks in application servers?"
  answer="* ThreadLocal: Provides thread-local variables where each thread accessing the variable gets its own independently initialized copy.
* Memory Leak Risk: In servlet containers (like Tomcat) that reuse worker threads from a thread pool, failing to call `remove()` on ThreadLocal variables can leave data attached to pooled threads indefinitely, causing memory leaks."
/>

<Flashcard
  question="What is the difference between Optimistic Offline Lock and Pessimistic Offline Lock patterns?"
  answer="* Optimistic Offline Lock: Resolves conflicts across multiple database sessions by checking version stamps when changes are saved; allows concurrent edits without long-lived database locks.
* Pessimistic Offline Lock: Prevents concurrent conflicts entirely by holding an exclusive lock on a business record across multiple database transactions from read until commit."
/>

<Flashcard
  question="What are the architectural trade-offs between Monoliths, Microservices, and Serverless?"
  answer="* Monolith: Simple to build and deploy initially, but difficult to scale or maintain as codebases grow large.
* Microservices: High scalability and independent deployability, but introduces distributed system complexity, network latency, and operational overhead.
* Serverless: Zero infrastructure management and automatic scaling with pay-per-execution pricing, but suffers from cold starts and vendor lock-in."
/>

<Flashcard
  question="What are the trade-offs between JSON and Protocol Buffers (Protobuf) serialization formats?"
  answer="* JSON: Human-readable, text-based format natively supported by web browsers, but has larger payload sizes and higher parsing overhead.
* Protocol Buffers: Binary serialization format that is exceptionally compact, parses rapidly, and enforces strict schema typing via `.proto` files, but requires specialized compilers and is not human-readable without decoding."
/>

<Flashcard
  question="What is a Feature Flag (Toggle) architecture and what are its trade-offs?"
  answer="* Definition: A development technique that allows developers to toggle application features on or off remotely without deploying new code or restarting services.
* Trade-offs: Enables dark launching, canary releases, and rapid rollbacks of faulty features, but introduces technical debt from stale flags and complex combinatorial testing states."
/>

<Flashcard
  question="What is Semantic Versioning (SemVer) and why is it important for API contracts?"
  answer="* Definition: A versioning convention structured as MAJOR.MINOR.PATCH (e.g., `2.4.1`).
* Rules: MAJOR version for incompatible API changes, MINOR version for backward-compatible functional additions, and PATCH version for backward-compatible bug fixes.
* Importance: Prevents breaking downstream microservice dependencies unexpectedly."
/>

<Flashcard
  question="What is the difference between Stateful and Stateless architectures?"
  answer="* Stateful Architecture: Servers retain client session state and data locally across multiple requests, requiring sticky sessions and complicating horizontal scaling.
* Stateless Architecture: Every incoming request from a client contains all necessary authentication and context data, allowing any server node in a pool to handle any request interchangeably for seamless horizontal scaling."
/>

<Flashcard
  question="What is Immutable Infrastructure and what are its primary benefits?"
  answer="* Definition: An operational paradigm where servers and infrastructure components are never modified in place after deployment; instead, if updates are needed, they are replaced entirely with newly built images.
* Benefits: Eliminates configuration drift, ensures exact environment consistency across staging and production, and simplifies rollback procedures."
/>

<Flashcard
  question="How does a Circuit Breaker test service recovery during its Half-Open state?"
  answer="* Mechanism: When a circuit breaker is in the Open state and a configured timeout elapses, it transitions to the Half-Open state.
* Testing: It allows a limited, controlled number of test request probes through to the downstream service; if these test requests succeed, the circuit closes (normal operation), but if any fail, it trips back to the Open state."
/>
